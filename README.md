# 跨国临床试验随机分组和揭盲控制台

源提示词摘要：研究中心按分层因素生成随机分组；药品管理员只见发药信息，研究角色正常情况下不可见治疗组；重复受试者和编号冲突被阻止；紧急揭盲需填写原因并形成不可删除审计记录，断网提交进入待处理队列。

## 技术栈

Nuxt 3、TypeScript、Element Plus、Pinia、Nuxt 路由、Axios、VueUse、VeeValidate、Zod、Vue I18n。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：`62028`

## 可用流程

- 中央台账：分层余量、受试者登记与安全审计共用一份中央记录（单一持久化状态），余量检查与发号在同一同步动作内完成，多中心管理员并发提交也不会穿透容量。
- 容量拒绝：分层名额已满的提交被拒绝并报出剩余名额；已入组受试者照旧保留。台账面板实时展示每层容量、已发号、剩余名额与放号状态。
- 配平重算：受试者状态变化（紧急揭盲）后自动重算所在区组的组别配平，重算期间该层锁定、暂停放号，完成后恢复并全程留痕。
- 角色隔离：药品管理员只见发药编号；治疗组与揭盲原因按角色边界隐藏（监察员可见已揭盲者组别，研究者可核对揭盲原因）。
- 容量调整：监察员可调整分层计划容量（不得低于已发号数），调整留痕。
- 防重复：相同身份标识或研究中心编号会拒绝再次入组。
- 安全审计：紧急揭盲要求原因，添加后只能追加，不能删除或改写。
- 离线队列：模拟离线提交进入待提交队列，联网后由授权人员确认入库，入库时同样受容量与锁定校验。
- 并发演示：随机卡片内的"模拟并发提交"按钮可一次发起 3 笔同层提交，观察超额拒绝与剩余名额回报。
