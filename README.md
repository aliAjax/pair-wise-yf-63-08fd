# 跨国临床试验随机分组和揭盲控制台

源提示词摘要：研究中心按分层因素生成随机分组；药品管理员只见发药信息，研究角色正常情况下不可见治疗组；重复受试者和编号冲突被阻止；紧急揭盲需填写原因并形成不可删除审计记录，断网提交进入待处理队列。

## 技术栈

Nuxt 3、TypeScript、Element Plus、Pinia、Nuxt 路由、Axios、VueUse、VeeValidate、Zod、Vue I18n。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：`62028`

## 可用流程

- 入组：机构、分层因素和受试者编号校验后生成分层区组随机号与治疗组；区组余量、受试者登记与安全审计共用同一份中央记录。
- 容量控制：每层设计划名额，放号原子完成；容量不足的提交直接拒绝并报出该层剩余名额，已入组记录保留不变。
- 并发提交：模拟多名中心管理员同时提交，中央记录串行放号，不会超排。
- 配平重算：受试者揭盲等状态变化后重算所在区组的组别配平，重算期间该层暂停放号，完成后自动恢复。
- 防重复：相同身份标识或研究中心编号会拒绝再次入组。
- 角色隔离：研究者可见随机号与治疗组；药品管理员只见发药编号（DY-随机号），治疗组与揭盲原因按角色边界隐藏；监察员仅在揭盲后可见治疗组。
- 安全审计：紧急揭盲要求原因，添加后只能追加，不能删除或改写；药品管理员视角下揭盲原因与治疗组信息脱敏。
- 离线队列：模拟离线提交进入待提交队列，联网后由授权人员确认入库，入库时同样校验容量与放号状态。
